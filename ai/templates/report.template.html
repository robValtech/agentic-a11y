Top 10 landmark best practices (not just for developers)

  1. Use native HTML elements, not just ARIA roles. Write <header> , <nav> , <main> , <aside> , <footer> — they carry their landmark role automatically. Only reach for role="region" etc. when a native element isn't available.
  2. One <main> per page, always. It identifies the primary content. Multiple <main> elements confuse screen readers and violate the spec.
  3. Label repeated landmarks. If you have two <nav> elements (e.g. primary + footer navigation), give each an aria-label: <nav aria-label="Primary"> and <nav aria-label="Footer"> . Same rule applies to multiple <aside> or <section> elements.
  4. Don't nest <main> inside other landmarks. <main> should be a direct child of <body> , sitting alongside <header> and <footer> — not buried inside a <div> soup.
  5. Use <section> with a heading, not as a generic box. A <section> only becomes a meaningful landmark when it has an accessible name via aria-labelledby pointing to a heading inside it. Without that, it's invisible to landmark navigation.
  6. Every page should have a skip link. Put <a href="#main-content" class="skip-link">Skip to main content</a> as the very first focusable element. It lets keyboard users bypass the nav on every page load.
  7. <header> and <footer> are context-sensitive. At the top level of <body> they create banner and contentinfo landmarks. Inside an <article> or <section> they are just structural — not landmarks. Don't over-use them.
  8. Avoid landmark overload. Every <section> with a label creates a landmark entry. A page with 20 landmarks is as hard to navigate as one with none. Aim for 6-8 meaningful regions max.
  9. Test with a real screen reader. VoiceOver (Mac/iOS: Cmd+F5), NVDA (Windows, free), or the Accessibility Tree in Chrome DevTools (F12 → Accessibility tab) will show you exactly what landmarks exist and how they're announced.
  10. Headings and landmarks work together — don't choose one. Landmarks let users jump between sections; headings (<h1>-<h6>) let users skim within a section. A great page needs both: proper landmark structure and a logical heading hierarchy that never skips levels.

About this report

This interactive accessibility report is based on the findings of an LLM running a fully automated, visual image analysis on a single static image file (typically a screenshot of a website or an artboard exported from Figma).

Use this tool to improve the non-visual experience on your page, and to catch accessibility issues early.

The report links to specific WCAG success criteria (opens in a new tab) where applicable, and it references WAI-ARIA APG (opens in a new tab) to help with accessibility best practices.

The contents of this report were generated by AI. To ensure accurate, reliable, and consistent output the LLM was provided with carefully constructed instructions, guard rails and validation checks – still, there can be mistakes and human review is always recommended.
